# AGENTS.md

AllyMailer Express — Express integration of the AllyMailer Node.js SDK (`@allymailer/allymailer-node-sdk`) for the AllyMailer transactional email Web API (Web API 1.90).

## Working on this repository

- **Generated code.** The whole package is generated by the AllyMailer team from the AllyMailer Web API OpenAPI spec (Web API 1.90): sources, docs, README.md and this file. Do not hand-edit it: the next release replaces the content of this repository. Report problems and requests in the issues of this repository (https://github.com/allymailer/allymailer-express).
- **Build and check:**

  ```bash
  npm install
  npm pack --dry-run
  ```

- **Source label.** Every request carries the query parameter `platform=express.1.0.0,node-sdk.2.0.0` (this package, then the SDK it is built on).
- **Tests.** Before a release the generator installs the package into a test app of Express and checks the client, the webhook endpoint and the mailer against a mock of the API: no real API key, no real sends.
- **Release.** The version (1.0.0 in package.json) and the tag `v1.0.0` come from the generator; README.md states the Web API version the release was generated from.
- **Secrets.** Never commit API keys; the examples read `ALLYMAILER_API_KEY` from the environment.

## Integrating AllyMailer with this package

Full guide: [README.md](README.md). Express integration of the [AllyMailer Node.js SDK](https://github.com/allymailer/allymailer-node-sdk) (`@allymailer/allymailer-node-sdk`): the API client in the Express app (middleware), a webhook endpoint with signature check, a Nodemailer transport that sends through `email/send`.

Install:

```bash
npm install @allymailer/express express nodemailer
```

Requirements: Node.js 18+, Express 4.18+ / 5.

Rules that generated code must follow:

- Server-side only. Read the API key from `ALLYMAILER_API_KEY`; never put it in browser or mobile code, never commit it.
- Base URL `https://cp.allymailer.com/ua/transactional/api/v1`; every method is POST with a JSON body; auth header `X-API-KEY`. The package does all of it.
- First email without DNS: `domain/get-sandbox-domain` → `confirmed-email/create` (the user clicks the link within 48 hours) → `email/send` from `noreply@<sandbox-domain>` to the confirmed address. Account API key only; up to 10 confirmed addresses, 100 emails a day; the domain expires after 31 days.
- Never ship a sandbox domain as the production sender (it is not in `domain/list`); read `from_email` from config. Production needs a verified domain: `domain/get-dns-records` → DNS records → `domain/validate-verification-record`, `domain/validate-dkim` → `domain/list`.
- Set `message.idempotence_key` on retryable sends; retry network errors, `429` and `5xx` with backoff, not other errors unchanged. Up to 500 recipients and 10 MB per request, each attachment up to 7 MB; always `body.html` or `body.plaintext`.
- Delivery events via webhook (`webhook/set`), not polling; the webhook endpoint of this package checks the `auth` signature of every notification.
- Keep the default unsubscribe and tracking behaviour; changes go through AllyMailer support.
- Do not invent methods or fields. Check the [README](README.md), the [API reference](https://docs.allymailer.com.ua/ua/web-api-ref) or [llms.txt](https://docs.allymailer.com.ua/llms.txt).

### Configuration

The API key goes to `ALLYMAILER_API_KEY`.

```bash
# .env
ALLYMAILER_API_KEY=YOUR_API_KEY
ALLYMAILER_HOST=cp.allymailer.com
```

| Option | Environment variable | Default | Description |
|---|---|---|---|
| `apiKey` | `ALLYMAILER_API_KEY` |  | User or project API key (required). |
| `host` | `ALLYMAILER_HOST` | `cp.allymailer.com` | API host (datacenter: `cp.allymailer.com`) or a full base URL. |
| `timeout` | `ALLYMAILER_TIMEOUT` | `30` | Request timeout, seconds. |
| `webhookKey` | `ALLYMAILER_WEBHOOK_KEY` |  | API key the webhooks are signed with (the key of the user/project of the webhook), if it differs from the API key. |
| `webhookPath` | `ALLYMAILER_WEBHOOK_PATH` | `/allymailer/webhook` | Path of the webhook endpoint. |

### Sending mail

Messages of the Nodemailer go through [email/send](https://docs.allymailer.com.ua/ua/web-api-ref#email-send): from, to/cc/bcc, reply-to, subject, HTML and text parts, attachments, inline images and `X-*` headers.

```javascript
import nodemailer from "nodemailer";
import { AllyMailerTransport } from "@allymailer/express";

const transporter = nodemailer.createTransport(new AllyMailerTransport()); // or { apiKey, host } / { client }

const info = await transporter.sendMail({
  from: "Shop <shop@example.com>",
  to: "user@example.com",
  subject: "Order shipped",
  html: "<b>Hello</b>",
  tags: ["orders"],           // -> tags
  metadata: { order_id: "42" }, // -> global_metadata
});
console.log(info.messageId); // job_id
```

### Webhooks

The endpoint answers `GET` with 200 OK (the URL check of [webhook/set](https://docs.allymailer.com.ua/ua/web-api-ref#webhook-set)) and accepts the `POST` notifications: it checks the `auth` field (MD5 of the request body in which the `auth` value is replaced by the API key), answers 401 to a wrong signature, and passes the notification and each of its events to the application.

```javascript
import { webhookRouter } from "@allymailer/express";

// before express.json(): the signature is checked over the raw body
app.use(webhookRouter({
  onEvent: async (event, user) => {
    console.log(event.eventName, event.eventData?.email, event.eventData?.status);
  },
  onNotification: async (callback, payload) => { /* the whole notification */ },
}));
app.use(express.json());
```

Register the URL of the endpoint with `webhook/set`, e.g. `https://example.com/allymailer/webhook`.
